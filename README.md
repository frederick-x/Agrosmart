# 🌱 AgroSmart – Smart Crop Recommendation System

A full-stack **decision-support** web app: a farmer enters soil and weather details and a **Random Forest** model recommends the most suitable crop, with an explanation, ideal conditions, growing period and general fertilizer advice.

**Stack:** React (Vite) + Bootstrap · Flask REST API · Scikit-learn · MySQL

## Folder structure
```
smart-crop-recommendation/
├── frontend/   React app (pages, components, services, context)
├── backend/    Flask API
│   ├── app.py  config.py  requirements.txt  .env.example
│   ├── routes/      URL endpoints (auth, crops, predict, history)
│   ├── services/    business logic (prediction + explanation)
│   ├── models/      SQL access for users, crops, recommendations
│   ├── database/    MySQL pool, crop seed data, init_db.py
│   ├── utils/       JWT auth + input validators
│   └── ml/          train_model.py, predict.py, crop_model.pkl
├── database/schema.sql
├── dataset/     crop_recommendation.csv + generate_dataset.py
└── docs/ACADEMIC_REPORT.md   (all 22 academic sections)
```

## How it works (data flow)
React form → `POST /api/predict` → Flask validates → `ml/predict.py` loads `crop_model.pkl` → Random Forest predicts crop + confidence → crop details read from MySQL → JSON back to React → ResultCard. If the farmer is logged in (JWT token), the prediction is automatically stored in `recommendations` (history). “Save Recommendation” flags it as saved for the dashboard.

## Setup (Windows/Mac/Linux)
Requirements: Python 3.10+, Node.js 18+, MySQL 8 running.

### 1. Backend
```bash
cd backend
python -m venv venv
venv\Scripts\activate          # Windows      (Mac/Linux: source venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env         # Mac/Linux: cp .env.example .env   -> edit DB_PASSWORD and SECRET_KEY
python -m database.init_db     # creates smart_crop_db, tables and loads 22 crops
python ml/train_model.py       # trains the model, creates ml/crop_model.pkl (re-run for your sklearn version)
python app.py                  # API on http://localhost:5000
```
Test: open http://localhost:5000/api/health → `{"success":true,...}`.

### 2. Frontend (new terminal)
```bash
cd frontend
npm install
npm run dev                    # http://localhost:5173
```
Vite forwards `/api` calls to Flask, so no extra config is needed.

## API
| Method | Endpoint | Auth | Purpose |
|---|---|---|---|
| POST | /api/register | – | create account (hashed password) |
| POST | /api/login | – | returns JWT + user |
| POST | /api/predict | optional | validate → ML → crop info (saves history if logged in) |
| GET | /api/crops?search= | – | list/search crops |
| GET | /api/crops/:id | – | crop details |
| GET | /api/recommendations[?saved=1] | ✔ | history |
| POST | /api/recommendations | ✔ | body `{recommendation_id}` marks as saved |

Example body for `/api/predict`:
```json
{"nitrogen":80,"phosphorus":48,"potassium":40,"ph":6.4,"temperature":24,"humidity":82,"rainfall":236,"soil_type":"Loamy","location":"Tamil Nadu"}
```

## Important notes (please read – good for your viva)
- **Dataset:** the included `dataset/crop_recommendation.csv` is **synthetic**, generated by `dataset/generate_dataset.py` around typical per-crop averages of the public Kaggle *Crop Recommendation Dataset*. For your final submission, download the real CSV from Kaggle (same columns: N,P,K,temperature,humidity,ph,rainfall,label), replace the file and run `python ml/train_model.py`. Report the accuracy printed on *your* data.
- **ML features:** N, P, K, temperature, humidity, pH, rainfall. **Soil type and location are NOT ML features** (they are not in the dataset). Soil type is compared with the crop's preferred soils in MySQL (“Suitable soil conditions” check); location is stored with the history only.
- **Confidence** = share of the 200 trees voting for the crop (`predict_proba`). Similar crops (e.g. rice vs jute at ~200 mm rainfall) can be close; the result card shows other close matches.
- No scaler is saved because Random Forest does not need feature scaling.
- Fertilizer/irrigation text is **general information**, not a prescription. Consult a local agricultural expert.

## Security
bcrypt-style salted hashing via Werkzeug (`generate_password_hash`), parameterised SQL, JWT-protected routes, CORS whitelist, secrets in `.env`, validation on both frontend and backend.

## Troubleshooting
- *Can't connect to MySQL*: check `.env` values and that MySQL is running.
- *crop_model.pkl not found / version warning*: run `python ml/train_model.py`.
- *CORS error*: make sure `CORS_ORIGINS` in `.env` matches the frontend URL.
